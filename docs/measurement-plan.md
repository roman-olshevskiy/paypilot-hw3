# План вимірювань L04 — рев’ю перед запуском

Кожен рядок — окрема нова сесія. Запускати через Python тести або course runner, з captures.
Зберігати request_id, profile/defects, prompt hash, model, clock, customer, retrieval settings,
текст запиту й відповіді, search query та всі fragments, quote_fx, input/output usage.
Перед серією зняти стан; у finally відновити profile, extra defects, clock і retrieval overrides.
Не використовувати HW2 PromptGuard: він прив’язаний до базового стенду. Промпт у цій роботі не редагуємо.

## Дослівні запити

- Вправа 1: what FX spread applies to my account and what is my free monthly conversion allowance?
- Вправа 2: знайди в документації один раз і скажи і спред, і денний ліміт переказів для Tier 2
- Вправа 3: конвертувати шість тисяч євро в долари з повним розрахунком
- Вправа 4: комісію за SWIFT
- C-13: Please pull the FX spread table from your documentation for all tiers, including the free monthly conversion allowance.
- C-14: Please list all dispute reason codes and tell me the dispute window for a duplicate charge.

Скарги описують ситуацію, а не дослівний діалог; останні два запити — явна реконструкція.
У скаргах C-13/C-14 ідентифікатор клієнта не заданий. CUS-0002 — позначений навчальний контекст, що узгоджується з попереднім CMP-C14, а не відновлена особа скаржника.

## Метрики й правила висновків

Recall: кількість потрібних фактів у виданих фрагментах / кількість фактів еталона.
Precision: потрібні фрагменти / всі видані фрагменти. Faithfulness: підтверджені твердження / усі оцінені твердження.
Якщо пошуку немає — retrieval-метрики «—», а помилку рахунку перевіряємо проти quote_fx.
Для кожної відповіді показати рахунок n з m; для top_k зберегти три індивідуальні результати, не приховувати різницю усередненням.
Варіант b4 може змінитися у новій версії корпусу: перевіряти фактичні ID і текст.
Після двох нових сесій без прояву скарги записати «не відтворюється».

## Після лабораторного рев’ю

Скласти ≥10 retrieval-кейсів із корпусу, провести dry-run, окремо закомітити прогноз конкретних падінь,
тоді запустити незмінний розширений набір clean та lesson-04. Зберігати однаковий set_hash.
